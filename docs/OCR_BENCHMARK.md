# OCR 측정 결과 (2026-11-27)

원본 수치: [OCR_BENCHMARK.json](OCR_BENCHMARK.json) · 재현: `.venv/bin/python tests/bench_ocr.py --real <폰 스크린샷 폴더>`

## 측정 환경
- macOS 15.7.5, Apple Silicon(arm64) 8코어, CPU 추론만 (GPU 미사용)
- Python 3.13.14 (설치 기준은 3.11 — 3.11 로는 실행 측정 안 함), onnxruntime 1.23.2, opencv 4.13.0
- 모델: PaddlePaddle 공식 Hugging Face ONNX
  - 검출 `PP-OCRv6_small_det` (rev 28fe589…) / `PP-OCRv6_medium_det` (rev 6132380…)
  - 인식 `korean_PP-OCRv5_mobile_rec` (rev 5c6f574…)
- 검출 입력: 원본 해상도 유지(1080x2400 → 32 배수 1088x2400), 후처리는 모델 yml 값(thresh 0.2, box_thresh 0.45, unclip 1.4)

## 정확도 — 합성 화면 100장 (정답 있음)
실제 앱과 같은 1080x2400 흰/회색 바탕에 앱 문구·상품명(한글 926줄)과 금액·주문번호·포인트·상품번호(숫자 465줄)를
24~64px, 진한/회색(저대비)/버튼(흰 글씨) 으로 그림. 글꼴: Apple SD Gothic Neo 3종 + AppleGothic.

| 검출 모델 | 한글 줄 일치 | 한글 문자 정확도 | 숫자 줄 일치 | 숫자 문자 정확도 | 놓친 줄 | 위치 오차(중심, 평균) |
|---|---|---|---|---|---|---|
| **PP-OCRv6_small_det** | 99.24% | 99.90% | **100.00%** | **100.00%** | 0 | 1.9px / 2.4px |
| PP-OCRv6_medium_det | 99.46% | 99.93% | 99.35% | 99.94% | 0 | 2.4px / 3.2px |

- 남은 오류는 대부분 인식 모델 쪽: `라운드랩`→`라운드램`, 문장 속 `10P`→`1OP`, 문장 끝 `.` 누락.
- medium 은 숫자 앞 `- `(차감 금액 표시)를 떼어 먹는 경우가 있었다.

## 속도 — 실제 폰 스크린샷 18장 (1080x2400, 다른 쇼핑앱 결제 화면)

| 검출 모델 | 전체 화면 평균 | 전체 p95 | 부분 화면(하단 400px) 평균 | 부분 p95 |
|---|---|---|---|---|
| **PP-OCRv6_small_det** | **957 ms** | 1,227 ms | **209 ms** | 557 ms |
| PP-OCRv6_medium_det | 5,217 ms | 5,910 ms | 883 ms | 1,180 ms |

같은 화면을 다시 읽으면 캐시로 0ms(추론 안 함).

## 결론
**small 채택** (`OCR_DET_MODEL` 기본값). medium 은 정확도 차이가 0.2%p 이내인데 5.5배 느리고 숫자 앞 기호를 놓쳤다.

## 목표 대비 (정직하게)
| 목표 | 결과 |
