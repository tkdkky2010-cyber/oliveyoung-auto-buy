## 2026-11-28 — UIAutomator dump 호출 최적화

### 목표
dump 1회 ≈ 3초(ORDER_STEPMAP 9 실측)가 최대 병목. UIAutomator 는 남기고 불필요한 호출만 줄인다.
상품·옵션·수량·배송지·금액·결제 검증과 보안 인증 절차는 약화하지 않는다.

### 그대로 둔 것 (일부러)
- 주문서·결제 화면 판정은 모두 resource-id 가 필요해 dump 유지. 이 단계들은 매번 탭·스와이프 직후라 캐시가 끼어들지 않는다(항상 새 dump).
- 카드앱 키패드(`ocr_keypad`)는 캐시를 거치지 않는 별도 dump — 보안 절차 변경 없음. 카드앱 화면은 캐시 제외(보안 화면·검은 스크린샷).
- Cloudflare 확인, 로그인 여부(닉네임 id), 로그아웃 버튼은 id 가 필요해 dump 유지.

### 측정 — 가상 폰 (실제 기기 아님)
비용 모델: dump 3.0초(실측) · 스크린샷 0.6초(가정) · OCR 0.9초(OCR 벤치 평균) · adb 명령 0.15초.
기존 = HEAD 085fa40, 수정 = 이번 작업. 수정 코드는 `DUMP_CACHE` 켜짐/꺼짐 결과가 같았다.

| 흐름 | 기존 dump | 수정 dump | 기존 시간 | 수정 시간 |
|---|---|---|---|---|
| 로그인 (입력 → Cloudflare 7초 → 로그인 → 계정 확인) | 5 | 5 | 18.8초 | 18.8초 |
| 로그인 실패 알림 → 확인 | 6 | **4** | 21.1초 | **14.2초** |
| 링크 진입 판정 (상품 페이지) | 1 | **0** | 4.5초 | **1.5초** |
| 링크 진입 판정 (로그인 폼) | 1 | 1 | 3.0초 | 4.5초 ⚠️ |
| 링크 진입 판정 (로딩 6초 → 상품) | 2 | **1** | 9.0초 | **6.0초** |
| 바로구매 → 옵션 → 수량 → 주문서 | 6 | **3** | 20.0초 | **11.0초** |

- 링크로 들어갔는데 로그인 폼이 뜨는 경우만 OCR 1회(약 1.5초)만큼 느려졌다. 시작할 때 항상 다시 로그인하므로 드문 경우로 판단.
- **dump 캐시 재사용은 모의 흐름에서 0회였다.** 줄어든 dump 는 전부 코드 변경(OCR 먼저, 읽은 화면 넘기기)에서 나왔다.
  처음 만든 캐시는 dump 마다 비교용 스크린샷을 새로 찍어서 오히려 느려졌다(로그인 18.8 → 21.8초, 주문서 11.0 → 12.8초) →
  이미 찍어 둔 스크린샷만 쓰도록 고쳐 추가 비용을 없앴다. 캐시는 같은 화면을 OCR 과 dump 로 번갈아 오래 읽는 경우에만 효과가 있다.
- 재현: `python tests/bench_dump.py --src phone_auto --cache 1` (기존 코드는 `git archive 085fa40 phone_auto` 를 풀어 `--src` 로)

### 검증
- pytest 73개 통과 (기존 63 + 새 10), macOS arm64 / Python 3.13.14.
- ⚠️ **실제 기기 미검증.** 실제 dump·스크린샷 시간, 캐시 재사용 횟수, 전체 처리시간은 폰에서 점검(dry-run)으로 측정해야 한다:
  대시보드 실행 로그의 `화면 읽기:` 줄을 `DUMP_CACHE=1` / `DUMP_CACHE=0` 으로 각각 비교.
